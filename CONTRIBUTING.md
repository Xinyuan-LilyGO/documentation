# Contributing Guide

## Basic Guidelines

- Documentation is written in Markdown
- All file and directory names must be **lowercase**, with words separated by hyphens `-`
- English and Chinese doc directories must mirror each other: paths under `en/` and `zh/` are identical

## Adding a New Product Page

### 1. Create the documentation files

Create the corresponding `index.md` in both English and Chinese directories simultaneously:

```
en/products/{series}/{product-name}/index.md
zh/products/{series}/{product-name}/index.md
```

Add frontmatter at the top of each file:

```yaml
---
title: Product Name
show_source: false
tags: LoRa, ESP32-S3, GPS
---
```

### 2. Place product assets

Each Markdown file corresponds to a same-named subdirectory under `public/products/{series}/{product-name}/`. For `index.md` the root is `index/`. Under that root, place files in the appropriate subdirectory:

```
public/products/{series}/{product-name}/index/
  image/        ← product photos (JPG/PNG)
  hardware/     ← schematics, PCB dimension drawings, DXF files
  firmware/     ← firmware binaries
  datasheet/    ← SoC and peripheral spec sheets (PDF)
  model/        ← enclosure and 3D model files
```

Recommended image naming: `{product-name}-1.jpg`, `{product-name}-2.jpg`, etc. The first image (`{product-name}-1.jpg`) is used as the product catalog cover.

### 3. Sidebar auto-update

The sidebar is auto-generated by scanning the filesystem on the next startup or hot-reload — **no manual config changes needed**.

## Product Page Structure

Each product page should organize content in the following section order. Optional sections may be omitted when content is not yet available and filled in later.

### Page header

```md
---
title: Product Name
show_source: false
tags: Tag1, Tag2, ChipName
---

# {{ $frontmatter.title }} <ShopLink href="https://lilygo.cc/products/..." />

<ImageGallery :columns="3" :images="[
  { src: '/products/{series}/{product}/index/image/{product}-1.jpg', alt: 'Front' },
  { src: '/products/{series}/{product}/index/image/{product}-2.jpg', alt: 'Back' },
]" />
```

### Overview (required)

Describe the product's main controller, supported features, use cases, and certifications in detail. The more thorough, the more useful for users evaluating or developing with the product.

### Quick Start (required)

Include the following (may link to separate documentation pages):

1. Arduino / ESP-IDF / MicroPython environment setup tutorials
2. Hardware assembly tutorials (soldering headers, installing antennas, etc.)
3. Third-party project tutorials (Meshtastic, SoftRF, etc.)
4. Factory firmware usage instructions

### Related Videos (required)

Product promo videos and tutorial videos. If a tutorial video overlaps with content in Quick Start, move the video into the relevant tutorial section rather than listing it separately.

### Key Features (required)

Concisely list the product's key features in list format.

### Specifications (required)

List parameters for each chip and peripheral. Recommended to include:

- SoC model and clock speed
- Flash / PSRAM size
- Wireless parameters (frequency band, protocol, output power, etc.)
- Peripheral sensor parameters
- Product weight
- Packaging dimensions

### Pinout (required)

List all GPIO mappings and describe which peripheral each GPIO connects to.

### Dimensions (required)

Include publicly available PCB dimension drawings and enclosure dimension drawings.

### Schematic (required)

Include publicly available PCB schematics.

### Datasheets (required)

Include publicly available SoC datasheets and peripheral sensor datasheets.

### Software Development (required)

List supported software driver libraries and example code links.

### FAQ (required)

Record product errata and answers to common user questions.

### Changelog (required)

Record the hardware/firmware version history for the product.
